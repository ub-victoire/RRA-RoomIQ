# Stage 8 Audit Action-to-Owner Matrix

This matrix is the S8-01 evidence catalog. It maps the audit actions explicitly named by the approved SRS to their owning service and inspected event implementation. A business event is not treated as an Audit event merely because its name resembles an audit action. “Implemented” in the status column means only the evidence described in that row; it does not mean Audit Service consumes the event or that S8-02/S8-03 has passed.

The Backend Requirements Specification (BRS) and Final Requirements Specification (FRS) DOCX files are authoritative. BRS §8.3 names the required audit facts and actions; BRS §5.2 and FRS §9.2 cover authentication/privilege and administrative requirements; BRS §7.3 requires versioned events with correlation/causation; BRS §8.4 requires correlation propagation and production-safe logging; FRS §9.4 governs data minimization and RRA-approved retention. The SRS does not define every event's field-level audit schema.

## Catalog boundaries and required follow-up

- Identity's `schemaVersion: 1` envelope is not the same schema as Booking/Room `eventVersion: 1`; do not normalize or silently extend either contract as part of this matrix.
- Booking and Room currently serialize a `causationId` property but their inspected producers pass `null`. Identity and Notification template-audit envelopes do not define causation. The approved `AUDIT_EVENT` schema stores `correlation_id` only. Whether source/causation must be persisted/searchable is unresolved and must be approved before adding fields or changing contracts.
- The SRS says safe metadata but does not define a universal field-level allowlist. Identity's generic `Map<String,Object>` parameter is not itself an allowlist. Only Notification template audit has an enforced per-event metadata field allowlist. Do not ingest Booking comments or other business payloads into Audit metadata without explicit approval.
- Business events from Booking/Room may satisfy producer-side business workflow needs; they are not Audit events and currently have no Audit consumer. Their available actor/scope/outcome facts are incomplete for the SRS audit record.
- No ERD or migration change is proposed or authorized by this catalog. Any necessary schema change must be proposed exactly and approved first.
- The user-approved `AUDIT_READ` role/scope policy is not implemented in Identity. It is not part of this S8-01 catalog work.
- Authentication failure is correctly representable with a null actor; no unauthenticated identity is inferred.
- No code, producer, database, or API was changed to create missing events. The rows marked missing/partial require separate S8-02 work and explicit approval of any new event type, payload, API, or schema.
